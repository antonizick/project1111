## [Unreleased]

### Added
- Phase 14: upscaling, logo text and the Models page. **Upscale** is a dialog on every result: ×1.5, ×2, to 1920x1080 or 2560x1440, **Speed** (model upscaler) or **Quality** (adds the refinement pass), and Generate gains a **Speed / Quality** toggle for the wallpaper presets (measured warm: Speed 15.8 s / 16.5 s, Quality 34.9 s / 76.6 s at 1920x1080 / 2560x1440, no OOM; ADR-0010 confirms `latent`). **Text overlay** (`recipe/steps/text_overlay.py`, `media/text.py`, ADR-0035): exact text drawn at full resolution with five bundled OFL fonts (`assets/fonts/`, hash-pinned in `fonts.json`, licences beside them), auto-fit, multi-line, alignment, anchor or drag-to-place, letter spacing, gradient, outline, shadow, plus "let the model try the text". New **Text & logo** dialog (live preview from `POST /api/text/preview`, `GET /api/text/fonts`), 6 logo variations, and a **logo pack** ZIP (transparent PNGs at 512/256/128/64/32 and `favicon.ico`, `POST /api/images/{id}/logo-export`). The three logo starters now draw a `logo_text` slot; the avatar starter gains its optional face swap (an optional slot left empty skips the step). **Models page** (`frontend/src/features/models/`): list by kind with state, size, sets and licence/commercial flag, install a set or a model after a licence acknowledgement dialog with live download progress, verify, enable/disable, remove, add from a file or URL; routes `/api/models/plan|install|verify|add|licences|operations`, `POST /api/models/{id}/enabled`, `DELETE /api/models/{id}`, SSE `models` and `models-changed`. Tests: text layout, font bundle, compile/job/API tests, Vitest for the Models page, text model and dialogs, Playwright (logo template with text slot; Models install flow against a local server), a `gpu` Speed/Quality test at both wallpaper sizes. ADR-0035.
- Phase 13: video face-swap. **Video view**: clip upload with the R13 limit warnings and a rough time estimate (over 60 s / 1080p needs an explicit "run it anyway" confirmation), face photo (upload, or **Use face in Video** on a result or gallery picture), the clip's first frame with clickable face boxes (the clicked face is followed across the clip by box overlap; "largest face in every frame" is the default), Fast / Good quality, frame-size cap, trim, temporal smoothing, keep-frames, frame progress with ETA and GPU temperature, Cancel (Esc too), **Resume** for interrupted runs, and a result player with Download. **Pipeline** (`jobs/video.py`, ADR-0033): probe → extract PNG frames (system ffmpeg, argument lists only) → S5 guard pre-pass (about 1 fps + scene changes) → per-frame face swap through the Phase 12 CPU path → optional GFPGAN → H.264 re-encode with the original audio (copied or AAC); progress persisted after every frame so a killed Studio resumes at the right frame with no duplicates; a user cancel deletes the scratch frames unless keep-frames is set. **The S5 guard runs on every swapped frame** (target and result) and a sampled pre-pass refuses the whole clip up front; no switch exists (ADR-0034). New routes `POST /api/video/frame`, `/api/video/detect`, `/api/video/jobs`, `GET /api/video/jobs[/{id}]`, `POST /api/video/jobs/{id}/resume`, `GET /api/video/jobs/{id}/file` (Range-capable); job rows gain `kind`/`spec` (migration v2). Output is an `.mp4` in the R7 layout with a JSON sidecar. Playwright: the video flow, the face picker and the limits confirmation. Measurements in `docs/P11_BENCHMARKS.md` → Video face-swap. ADR-0033, ADR-0034.
- Phase 12: face, pose and reference. **Face & Pose view** with four tools: **Swap face** (choose the picture and a face photo, click the face to swap onto when there are several, Blend, Restore afterwards; a consent notice "Use faces of people who agreed."), **Apply pose** (prompt + a pose from the built-in editor or a photo; Body pose / Depth / Lines control; strength), **Use as reference** (Style and colours or The person; strength), **Restore faces** (one face or every face). Inline **Face** actions on results and gallery detail open the view with that picture. **Pose editor** (`frontend/src/features/pose-editor/`): drag joints on an SVG skeleton, mirror, five stock poses (standing, sitting, waving, arms crossed, headshot), add/remove people; the skeleton it draws is exactly the OpenPose picture the ControlNet reads (`POST /api/pose/render`). **Face pipeline** in P11 on the CPU (`media/faces.py`, ADR-0028): YuNet detection + 5 landmarks, ArcFace w600k-r50 embedding, `inswapper_128` swap, GFPGAN v1.4 restore with blend and strength; ~2.4 s per swap, +1.5 s restored, no VRAM. **The S5 NSFW target guard** (ADR-0029): two pinned classifiers (Marqo ViT-tiny + Freepik EVA02), fixed thresholds, either one refusing is enough; checked on the target before the swap and again on the result, and at submit time when the target is already a file; fails closed when the models are missing; no setting, flag, env var, route or recipe field names it (a test greps for one). **Pose** (`recipe/steps/pose.py`, ADR-0030): ControlNet Union SDXL ProMax through the core `ControlNetLoader` → `SetUnionControlNetType` → `ControlNetApplyAdvanced`, with the map made in P11 (`media/pose.py` DWPose skeleton, `media/control.py` Depth Anything V2 Small and OpenCV Canny) as a `GraphInput.transform`. **Reference** (`recipe/steps/reference.py`, ADR-0031): IP-Adapter Plus / Plus Face through P11's own `engine/custom_nodes/p11_ipadapter` node pack (the only custom node the engine may load; its SHA-256 is pinned in `engine.lock.toml` and checked by `engine_setup.sh`), with the CLIP ViT-H encoder loaded by ComfyUI's core `CLIPVisionLoader`. New routes `POST /api/face/detect`, `/api/pose/extract`, `/api/pose/render`. 13 new hash-pinned models in the new `face` and `control` sets (both also in `full`; `default` unchanged at 14.63 GB); the InsightFace entries are **non-commercial** and need an acknowledgement (`p11 models install face --accept-licences`). Measurements in `docs/P11_BENCHMARKS.md` → Face, pose and reference. ADR-0028…0032; ADR-0011 decided in ADR-0028.
- Phase 11: background replacement. A Background view (open from a result, the gallery or an uploaded photo; P11 finds the subject automatically with a spinner and shows the mask overlay; **Refine mask** opens the mask editor seeded with the auto-mask (`MaskEditor.initialMask`); background sources: photo upload, **Describe** (generates a background from a prompt at the subject's closest aspect), flat colour or transparent PNG; blend: Harmonize Off/Light/Strong, colour match (on by default), edge feather, drop shadow; Advanced fit/position/size; live preview through `/api/background/preview`, which runs the same pipeline Apply saves). The `replace_background` step segments the subject (BiRefNet-lite ONNX on the CPU, `media/segment.py`, manifest entries `birefnet-lite` default and `birefnet` full, both MIT and hash-pinned) and composites in P11 (`media/composite.py`: fit/place, LAB colour match at a chosen strength, edge decontamination, feather, shadow, RGBA output for colour/transparent); `relight` adds a low-denoise harmonize pass over the seam band on the engine. New routes `POST /api/background/mask` and `/api/background/preview`. Save as Template offers "find the subject each run" (default for background runs) so a "product on my studio background" template re-runs on any new subject. Tuning and measurements on the laptop (`scripts/bench/background_tune.py`, `docs/P11_BENCHMARKS.md` -> Background replacement); Playwright: the Appendix B background path is 4 actions. ADR-0026, ADR-0027.
- Phase 10: inpainting. Mask editor (`frontend/src/features/mask-editor/`: brush and eraser, size with `[`/`]`, hardness, opacity, feather preview, invert, clear, undo/redo with Ctrl+Z/Ctrl+Shift+Z, wheel/pinch zoom, space- or middle-drag pan, pen pressure; greyscale PNG export at image resolution; 60 fps on 2560×1440) and an Inpaint view (open from a result, the gallery or an uploaded photo; prompt prefilled; Subtle fix / Change / Replace; "only masked area at full resolution"; Advanced denoise, mask blur, padding, steps, seed; Keep editing; Save as Template). The `inpaint` step compiles to core ComfyUI nodes (`recipe/steps/inpaint.py`); the runner grows and blurs the mask at full size, crops and scales the masked area to the model's working size and pastes the result back so unmasked pixels stay byte-identical (`media/inpaint.py`, `MaskPrep`); empty masks are refused at submit (`input.mask`). Save as Template can keep the mask in the template or ask for one each run. Presets tuned on 10 images on the laptop (`scripts/bench/inpaint_tune.py`, `docs/P11_BENCHMARKS.md` → Inpainting). Playwright: inpaint path 4 actions. ADR-0025.

### Changed
- Phase 14: `TextOverlay` gains `weight`, `colour2`, `align`, `x`, `y`, `letter_spacing` (additive, no schema bump); `compile()` no longer advances its previous-step pointer for a step that compiles to nothing; `FaceSwap` is skipped when its optional face slot is empty; `upscaleRecipe` takes options (Quality / target size) and the Upscale button opens a dialog; the Models nav entry is live; `ModelInfo` in the UI types carries the full status object; the test-only `P11_ALLOW_LOOPBACK_MANIFEST=1` lets the manifest and downloader use `http://127.0.0.1`; the Playwright config starts a loopback model server.
- Phase 13: `jobs.db` migration v2 adds `kind` and `spec` columns (video jobs carry a `VideoSpec` instead of a recipe); `Job.summary` and `/api/jobs` carry `kind`; `JobControl.cancel` gains `purge` (a user cancel may drop a video job's scratch, a shutdown never does); `StudioPaths` gains `scratch` (the video scratch root, sandboxed under `--fake`). Frontend: `Upload` types `seconds`/`warnings`, the upload kind `video`, and the Video nav entry is live (Models stays a Phase 14 placeholder). Fixed: the Face & Pose view now hides when another view is open (it stayed visible under the others).
- Phase 12: additive schema changes (ADR-0032): `FaceSwap.blend`, `Pose.control` (`openpose`/`depth`/`canny`) and a new `face_restore` step type; older v1 documents still load, so no schema version bump. `GraphInput` gains `transform` (the picture preparation the runner applies before upload: `pose`, `depth`, `canny`, `reference`). The manifest gains kinds `classifier`, `preprocess` and `clipvision` and sets `face` and `control`; `p11 models install face|control` installs them. The engine's launch flags now whitelist P11's own `p11_ipadapter` node pack (`--disable-all-custom-nodes --whitelist-custom-nodes p11_ipadapter`), `extra_model_paths.yaml` maps the `clip_vision` folder, and `p11.recipe.registry.PROVISIONAL_DEFAULT_SET` grew the 13 new models. Dependencies added: `opencv-python-headless` 5.0.0.93 (Apache-2.0) and `onnx` 1.23.2 (Apache-2.0, for the swapper's embedded projection matrix).
- Phase 11: `ReplaceBackground` grows additively (optional `background_slot` + `background_colour` exactly one of; `mask_png`, `colour_match_strength`, `prompt`/`negative`, `fit`, `background_x`/`background_y`, `subject_scale`, `subject_x`/`subject_y`, `shadow`; `mask_mode: auto` takes no mask); older v1 documents still load. The compiler's `compile()` now returns plan items (`EngineGraph | LocalStep`) and `register_plan_step` covers steps that are local work with an optional engine tail (`GraphInput` gains `local` sources); the runner executes local steps in `p11.media` and saves only a step's last output. `POST /api/templates/from-image` takes `mask: auto|slot|fixed`. `MaskEditor` gains `initialMask`. The default model set grows by `birefnet-lite` (14.41 GB -> 14.63 GB, within the 30 GB budget; recorded in the manifest and ADR-0026).
- Phase 10: `Inpaint` gains optional `mask_png`, `mask_blur_px`, `crop`, `padding_px` and `sampler` and `mask_slot` becomes optional (exactly one of `mask_slot`/`mask_png`); older v1 documents still load, so no schema version bump (ADR-0025). `EngineGraph` gains `prep`, `GraphInput` gains `inline` inputs and `kind`; `POST /api/templates/from-image` takes `mask: slot|fixed`; template slot uploads of `mask` slots go up as `kind=mask`; the Inpaint nav entry and result/gallery Inpaint button are live (`NavProvider.edit`).
- Phase 09: the Templates nav placeholder and the `LATER.template` stub are replaced; template export files are named `<slug>.p11template.json` (was `.p11.json`); `create_app(starters=…)` and `Studio.starters` install the bundled starters (off unless `p11 serve`); the gallery route helpers `entry_file` and `run_record` are shared with the templates route.
- Phase 08: the placeholder page is replaced by the Studio UI; `GalleryIndex.delete` clears the parent link of children; `search`/`search_count` take `model`.
- Phase 07: `create_app()` takes settings, session, port and paths and always has an engine (the pinned ComfyUI unless `fake`); the gallery index gains `since`/`until` filters and `search_count`; the FakeEngine returns one image per batch item, like ComfyUI; new settings `engine_idle_stop`, `video_warn_seconds`, `video_warn_height`; the Playwright e2e runs against `p11 serve --fake` in temp dirs; the coverage gate includes the API, jobs, media, lifecycle, doctor and logging modules; dev dependency `httpx2` (BSD-3-Clause) removes Starlette's `TestClient` deprecation warning (open since Phase 02).
- Phase 06: the `models` CLI stub is replaced; the coverage gate includes `p11.models`; `p11.recipe.registry.ModelKind` gains `facedetect`; `PROVISIONAL_DEFAULT_SET` is now a test fixture kept equal to the manifest by a test.
- Phase 05: thermal guard defaults are 87 °C pause / 80 °C resume (owner question 5, H9; were 83 / 75 placeholders) and must satisfy resume < pause; the Phase 04 compiled-graph `gpu` test runs through `ComfyEngine`; the coverage gate in `make test` now includes `p11.engine` and `p11.gpu`.

### Fixed
- Phase 12: `p11.models.state._atomic_write` now creates P11's own state directory with `0700` (it used a plain `mkdir`, so `~/.config/p11` came out `755` under the default umask and the licence acknowledgements inside were listable by other users). Found by `p11 doctor`'s permissions check during the Phase 12 acceptance run.

## Tasks
1. **Build stamp (ADR-0043).** A small module, for example `src/p11/webbundle.py`: `source_hash(repo_root)` is the SHA-256 over the frontend inputs (`frontend/src/**`, `frontend/index.html`, `frontend/package-lock.json`, `frontend/vite.config.ts`, `frontend/public/**` if present), sorted and path-prefixed. `write_stamp()` writes `src/p11/web/build-info.json` (`source_hash`, `built_at` timestamp, `version`, short git commit if available). `status()` returns `current | stale | missing | no-sources` (an installed tree without `frontend/` is `no-sources`, not stale). Use one implementation (Python), called by `make build` after `npm run build` and by `install.sh`. Never call the build from `p11 serve`, which must not need npm.
2. **Rebuild when stale.** In `install.sh` step 5, build when `status` is `missing` **or** `stale`, and say which in plain English. `--dry-run` reports "would rebuild the frontend (sources changed since the last build)". `p11 update` inherits this through `install.sh`. Add a test that runs `p11 update` from a tag whose frontend differs and asserts the bundle is rebuilt (container test or a unit test of the decision).
3. **Make staleness visible.** `p11 doctor` gets a "Studio frontend" check: green when current, a warning with the hint "Run `make build` (or `./install.sh`), then `p11 stop && p11 start`" when stale. `p11 status` prints the bundle id (short hash) and "stale" when it is. `p11 serve` logs a WARNING at startup when stale. The Studio shows its build id unobtrusively (status-bar tooltip or Settings/About), so Nick and agents can match the window to the build. `/healthz` may add `web` (the short hash; no paths or prompts, S6) if it helps the verification script.
4. **No stale `index.html` in the app window.** Serve `index.html` (and `/` and the SPA fallback) with `Cache-Control: no-cache`. Hashed `/assets/*` may stay cacheable. Add a test for the header. Check that Brave's app window picks up a rebuilt bundle on reload.
5. **Close-out rule (process).** In `prompts/P11_shared-instructions.md` §4, add a required item: "If the phase changed anything under `frontend/`: after the merge, in the main checkout run `make build`. If `p11 status` shows the Studio running, run `p11 stop && p11 start`. Confirm `p11 doctor` reports the frontend current and record the bundle id in the Phase Log." Also add: "Acceptance criteria that name the real Studio are checked against the main checkout's Studio (port 8111) in Nick's app window or at its size, not only against `p11 serve --fake` in a worktree. If that is impossible in the session, the phase says so plainly in the final message and does not claim it." Mirror the step in `.claude/commands/phase.md` if it repeats the close-out list.
6. **Re-verify the four items at Nick's real window size.** Extend `frontend/e2e/ui-fixes.spec.ts` and `photo-edit.spec.ts` with a **1918×2130** viewport case (plus 3840×2160 for the overlay), for overlay alignment, Face & Pose bounds and scrolling, the stroke path, and the photo thumbnail. If Playwright's `chromium.launch({ executablePath })` can drive the installed Brave (`/usr/bin/brave` or the Omarchy path), run the same specs once in Brave too. Otherwise record why not. Any failure is a real defect: fix it at the root, with a failing check first.

- `index.html` responses carry `Cache-Control: no-cache`.
- **Nick confirms in his own Studio window** (Brave app window, his normal size) that all four items work as he described them. His answer is recorded in owner question 23 with a timestamp. Without that confirmation the phase does not claim the items are fixed. In hands-off mode it blocks with question 23 instead of closing.
